# 풋프린트 라이브러리 규칙 (Allegro / IPC-7351B)

## 검증 상태

| 항목 | 상태 |
|---|---|
| 계산 공식 구조 (Zmax / Gmin / Xmax) | IPC-7351B 그대로. 신뢰 가능 |
| chip 수동부품 8종 산출값 | **잠정** — 필렛 상수 미검증 |
| 디스크리트 13종 | 치수 미입력. datasheet 필요 |
| 필렛 상수 (JT/JH/JS), F, P, CE | **미검증** — 아래 절차로 대조 필요 |

`ipc7351.py` 상단 `VERIFY_REQUIRED = True` 인 동안 출력은 전부 잠정값이다.
상수 대조를 마친 뒤에만 `False` 로 바꾸고 심볼 생성에 쓴다.

### 상수를 검증하는 방법

`FILLET_GOALS`, `F_FABRICATION`, `P_PLACEMENT`, `COURTYARD_EXCESS` 를
다음 중 하나와 대조한다. 1행만 맞으면 나머지는 공식이 보장한다.

1. IPC-7351B 원문의 패키지 패밀리별 필렛 목표 표 (권위 있는 출처)
2. PCB Libraries 의 IPC-7351 LP Calculator / LP Wizard 무료판 — 검증된 구현체
3. KiCad 표준 라이브러리의 IPC 준수 풋프린트 — 교차 확인용

대조 절차: 0603 한 개를 위 도구로 생성해 `pad X / pad Y / gap / c2c` 를
`python3 ipc7351.py --level B` 출력과 비교한다. 어긋나면 상수를 고친다.

### 이미 발견해 고친 오류 (기록용)

chip 수동부품에 걸윙용 힐 필렛(JH = 0.35)을 적용했더니 0201/0402/0603 에서
패드 간격이 음수로 나왔다. chip 단자는 바디 밑으로 감싸 들어가 힐 필렛이
물리적으로 형성되지 않으므로 `JH = 0` 이 맞다. `validate()` 가 이 오류를
잡았다 — 상수 오류는 이렇게 물리적 모순으로 드러난다.

## 설계 규칙

### 1. 패드 치수의 출처 — datasheet 우선

부품마다 출처는 **하나**다. 섞거나 겹쳐 쓰지 않는다.

```
datasheet 에 권장 랜드 패턴이 있는가?
├─ 있다  -> 그 패턴 그대로 사용. 밀도 등급 개념 적용 안 함.
│           (IC 대부분, 커넥터, 크리스탈/오실레이터,
│            전력 패키지, QFN/DFN, BGA, 실드 인덕터)
└─ 없다  -> IPC-7351B 로 계산. 등급은 하우스 기본값.
            (chip 수동부품, 소형 디스크리트, 표준 SOIC/SOP/QFP/SOT)
```

IPC-7351 은 리드 부착 형상만 다룬다. 다음은 계산으로 나오지 않으므로
반드시 datasheet 가 필요하다: QFN/DFN 써멀 패드와 그 아래 비아 패턴,
BGA 볼 패드 방식(NSMD/SMD), 페이스트 축소율, 커넥터·크리스탈 keepout.

### 2. 밀도 등급 — 프로젝트 단위로 한 번만 결정

밀도 등급은 부품의 속성이 **아니다**. 보드 밀도와 조립 공정을 기준으로
설계자가 고르는 값이며, 패드 크기와 면적의 트레이드오프 설정이다.

| 등급 | 접미사 | 성격 |
|---|---|---|
| A (Most) | `M` | 넉넉. 저밀도 보드, 리워크·검사 용이 |
| B (Nominal) | `N` | 표준 |
| C (Least) | `L` | 최소. 고밀도, fine pitch |

**등급 문자(A/B/C)와 이름 접미사(M/N/L)가 다르다.** Level A -> `M`.

**이 프로젝트 하우스 기본값: Level A (Most)** — 손 조립·리워크 빈도를 고려.

- 부품별로 골라 쓰지 않는다
- 보드 리비전별로 바꾸지 않는다
- 개발보드와 양산보드가 **같은 라이브러리**를 쓴다
- 예외는 공간 제약이 증명된 경우만, 근거를 심볼 설명에 기록

### 3. 개발보드 / 양산보드

풋프린트를 분기하지 않는다. 개발보드의 목적은 양산될 것을 검증하는 것이고,
패드 형상이 다르면 수율·틸팅·보이드 데이터가 양산에 전이되지 않는다.

| | 개발 | 양산 |
|---|---|---|
| 풋프린트 심볼, 밀도 등급 | 동일 | 동일 |
| 테스트 포인트 구리 | 있음 | 그대로 있음 |
| 디버그 커넥터/점퍼 | 실장 | DNI (배리언트) |
| 패널화, fiducial | 없음 | 양산 아트워크 |

차이는 **실장 여부(배리언트)와 파브 데이터**로만 표현한다.

인두 접근성은 패드 크기가 아니라 다음으로 확보한다 (효과 큰 순서):
부품 간격(courtyard) > GND 패드 써멀 릴리프 > 패키지 선택(QFN 대신 SOIC)
> 마스크 dam 유지 > 부품 방향 정렬.

### 4. 심볼을 나누는 기준

구리/마스크 형상이 **실제로 다를 때만** 나눈다.

| 다른 항목 | 심볼 분리 |
|---|---|
| 부품 등급(AEC-Q200, 온도), 오차, 정격, 벤더, MPN | 안 함 |
| 밀도 등급 | 안 함 (프로젝트당 하나) |
| 벤더별 써멀 패드 치수가 다른 QFN | 함 — 사실상 다른 패키지 |
| BGA NSMD vs SMD | 함 |

여러 MPN 은 part table 에서 하나의 `.psm` 에 바인딩한다.

### 5. 명명 규칙

```
CHIP     : {prefix}{LL}{WW}X{HH}{접미사}          RESC1608X45M
그 외    : {prefix}{피치}P{span}X{높이}-{핀}{접미사}   SOT95P237X112-3M
datasheet: 형상명 + 출처 표시                      QFN50P400X400X80-25_MFR
```

datasheet 패턴에는 `M/N/L` 접미사를 붙이지 않는다 (계산으로 나온 값이
아니므로 거짓 정보가 된다). `_MFR` / `_TI` / `_DS` 로 출처를 표시한다.

심볼 설명 필드에 근거 문서와 리비전을 기록한다:

```
"TI SN74LVC1G08 QFN-8, land pattern per SLUA271 Rev.C, 2023-04"
```

- 하이픈 대신 언더스코어 사용 여부는 프로젝트 시작 시 확정 (툴체인 호환)
- 31자 이내 유지

### 6. datasheet 플로우의 함정

1. **벤더별로 "같은 패키지"가 다르다.** 세컨드 소싱 시 두 datasheet 의
   랜드 패턴을 반드시 대조. 부품은 호환인데 풋프린트가 비호환인 경우가 있다.
2. **리비전 드리프트.** Rev A 와 Rev D 의 패턴이 다를 수 있다. 근거 리비전 기록.
3. **datasheet 가 안 주는 것**은 하우스 룰로 통일: 솔더마스크 개구(편측
   0.05mm), 페이스트 규칙, courtyard 여유.
4. **단위와 축척.** mil/mm 혼용, "NOT TO SCALE" 표기. 숫자를 읽고 도면을 재지 않는다.
5. **Minimum 과 Recommended** 가 같이 있으면 Recommended 를 쓴다.

## 사용법

```bash
python3 ipc7351.py                    # 하우스 기본값(Level A)
python3 ipc7351.py --level A B C      # 등급 비교
python3 ipc7351.py --csv out.csv      # 결과 저장
```

물리적으로 성립하지 않는 결과(패드 간격 음수, 마스크 dam 미달)는
`FAIL` 로 표시되고 exit code 1 을 반환한다. 이 경우 심볼을 만들지 않는다.

## 파일

| 파일 | 역할 |
|---|---|
| `packages.csv` | 부품 치수 원본. 사람이 관리하는 단일 진실 원본 |
| `ipc7351.py` | 계산기. 패드 형상 / courtyard / 심볼명 산출 |

`.psm` / `.pad` 는 재생성 가능한 산출물이다. `packages.csv` 가 원본이다.

## 남은 작업

1. 필렛 상수 검증 (위 절차) -> `VERIFY_REQUIRED = False`
2. 디스크리트 13종 치수를 실사용 부품 datasheet 에서 입력
3. 커패시터/인덕터 행 추가 (`CAPC` / `INDC`, 높이만 다름)
4. 하우스 룰 확정: 솔더마스크 개구, 페이스트, courtyard, 하이픈/언더스코어
5. Allegro 심볼 생성 — 수량이 20~30개면 Symbol Wizard 로 수동이 더 빠름.
   그 이상이면 SKILL 스크립트
6. 검증 스크립트 — `extracta` 출력에서 마스크 sliver, 패드 간격, courtyard
   충돌, 심볼명 규칙 위반, 중복 심볼 감사
7. first-article 검증 — 1:1 출력 대조, QFN/BGA 는 X-ray
