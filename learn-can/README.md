# STM32G4로 배우는 CAN / CAN FD 통신

> 대상: **하드웨어 경력은 풍부하지만 C 언어·펌웨어가 처음인** 엔지니어
> 보드: **STM32G4 Nucleo** (FDCAN 내장 → Classic CAN + CAN FD 모두 가능)
> 목표: 자동차급 CAN 개발 흐름을 손에 익혀 **태양광 인버터 / BMS / 모터제어**로 이식

---

## 왜 이 순서인가

CAN FD는 CAN(Classic)에서 **데이터 구간만 빨라진 확장판**입니다.
Classic을 확실히 하면 FD의 95%를 이미 한 것입니다. 그래서 **Classic → FD** 순서로 갑니다.

```
[중재 구간]      [데이터 구간]      [ACK]
 느림(500k 고정)  FD는 여기만 빨라짐   느림
 = 모든 노드 경쟁  = 송신자 1개뿐       = 수신 확인
 → 버스 길이가      → 아무도 경쟁 안 함
   속도를 제한         → 2~8Mbps 가능
```

- **중재 구간**: 모든 노드가 동시에 비트 경쟁 → 버스 양끝 신호 왕복 시간 필요 → 속도 못 올림
- **데이터 구간**: 중재 끝나면 송신 노드는 하나뿐 → 경쟁 없음 → 여기만 빠르게

하드웨어 관점: `중재 = 오픈드레인 와이어드-AND 경쟁`, `데이터 = 단일 드라이버`.

## 3개의 디버깅 계층 (헷갈리지 말 것)

| 계층 | 도구 | 무엇을 보나 |
|---|---|---|
| ① 코드 레벨 | ST-Link (Nucleo 내장 디버거) | C 코드 한 줄씩, 변수, 브레이크포인트 |
| ② 버스 레벨 | **PCAN-USB FD** + PCAN-View | 버스 위 CAN 프레임 전부 (ID·데이터·타이밍) |
| ③ 응용/보정 레벨 | **INCA** (XCP over CAN) | ECU 내부 변수 실시간 읽기·튜닝 (뒤 단계) |

> **PCAN은 "두 번째 노드"를 대신할 수 있습니다.** 보드 1개 + PCAN이면 실제 버스 통신 학습 가능.

## C 언어는 따로 공부하지 마세요

이 실습에 나오는 것만 그때그때 익히면 충분합니다:

| 문법 | 하드웨어로 치면 | 어디서 |
|---|---|---|
| `uint8_t`, `uint32_t` | 8비트/32비트 레지스터 폭 | CAN 데이터·ID |
| `배열 data[8]` | 연속된 8칸 메모리 | CAN 페이로드 |
| `struct` | 여러 필드를 묶은 커넥터 핀맵 | CAN 프레임 헤더 |
| `& | << >>` | 비트마스크·시프트 (데이터시트 그대로) | 레지스터·플래그 |
| 함수, `if`, `while` | 순차 실행 흐름 | 전체 |
| 인터럽트 콜백 | 트리거 신호 오면 처리 | CAN 수신 |

두어 달 뒤 실습이 손에 익으면 그때 C 책 한 권 훑으면 빈틈이 메워집니다.
**"필요할 때 배우는" 순서가 하드웨어 엔지니어에게 가장 빠릅니다.**
